# 01 機台與韌體

## 識別

- 型號：nüvi 2565RT 台灣版，HWID 1352，軟體 8.00。
- 機台 XML 宣告 `Map/*.img` 與 UnicodeMaps，所以能載入自編 IMG 圖資。
- 診斷頁（使用者手抄）：SW 8.00、nuvi26xx A V3 4GB 128MB、PCB3。128MB 只是畫面上的容量標籤，
  不等於實測 RAM 或可用 heap；RAM/ROM Test「Ready」也不代表測試通過。
- USB：一般使用時是隨身碟（Mass Storage，VID:PID `091e:2548`）。手冊把車架的圓形視訊輸入埠與
  GDR10 microUSB 埠分開；沒有找到通用 USB host 或對外供電的官方資料。

## 韌體結構

- `scripts/analyze_gcd.py` 解析台灣 8.00 的 GCD 更新檔：742 筆記錄可完整重建，4 個累加 CheckPoint 校驗通過。
- BOOT／MAIN 入口、HWID、版本與結束標記一致指出載入基址為 `0x50000`。
- MAIN 校驗通過；BOOT 的校驗規則與尾端 260 bytes 用途未知，所以**不能**據此產生可刷寫的更新檔。
- MAIN 內有 STA2064 驅動原始碼路徑，與 ST 的 ARM1176 平台相符。

## 記憶體配置重點

| 項目 | 內容 |
| --- | --- |
| 已初始化資料 | 由 `0xCB1980` 搬到 `0xF00000`，長度 `0x7224C` |
| 兩段條件式程式 | runtime `0x04400000`、`0x05400000`，合計 4,365,400 bytes |
| 語音模組保留區 | `0x02D4BB74` 起 3 MiB；原廠語音實際使用後還剩 58 萬～111 萬 bytes |

找資料引用時要使用 runtime 位址，不能把同一個差值套用到所有程式或資源。
`scripts/analyze_native_sections.py` 可重建 copy／zero 範圍。

## 藍牙

- SDP 解出 14 組服務範本、106 個屬性；有 Audio Sink 範本（handle `0x90007`），但開機只啟用 SPP、Handsfree、PBAP 等。
- 未公告的 AVDTP PSM 25 可以連上，Discover 回覆沒有任何端點。代表協定有在運作，但原機沒有啟用 A2DP Sink。
- 原廠藍牙手機資料庫（`BTM 006-D1283-01.bin`）的編碼為每 byte XOR index XOR `0x69`，解出 537 筆手機設定，
  沒有可辨識的音樂開關。

## 語音模組與程式載入

原廠 TTS 語音包（`Voice/*.vpm`）內含 `DLLIMG.BIN`，由原廠載入器讀進保留 RAM、做重定位並註冊 40 個介面。
這是目前找到唯一能讓自製程式碼在原機執行的入口，詳見 [05 原生程式與 GarminOS](05-原生程式與GarminOS.md)。

`DLLIMG.SIG` 為 72 bytes 的 OpenPGP v4 簽章封包，宣告 DSA／SHA-1；原機是否強制驗證、公鑰在哪裡都還不知道。
實機上已確認一個**修改過程式碼**的語音包能被選用並執行，但這只代表該候選檔，不能推論所有修改都會被接受。
