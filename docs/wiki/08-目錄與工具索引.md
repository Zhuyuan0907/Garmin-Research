# 08 目錄與工具索引

## 資料夾

| 資料夾 | 內容 |
| --- | --- |
| `scripts/` | 約 720 個 Python 腳本，研究的主要工具 |
| `native/` | 自製 C／ARM 組語原始碼與 linker script |
| `android/garmin-hfp-player/` | Android App 原始碼與主機端測試 |
| `evidence/` | 研究證據 JSON；`evidence/firmware-analysis/` 是韌體分析與模擬結果 |
| `evidence/research-checkpoints/` | 各輪研究狀態快照 |
| `staging/<主題>-v<n>/` | 各輪實驗的工作目錄：當時的程式快照、proof、seal、終端執行紀錄 |
| `reports/nuvi2565RT.html` | 研究報告網頁（原本由 Pi 區網服務提供） |
| `services/` | 報告網頁的 systemd unit |
| `sources/` | 第三方來源的下載網址與雜湊紀錄 |
| `docs/` | Wiki、研究日誌（`research-log.md`）、Android Auto 查核文件 |

## 腳本命名

| 前綴 | 意義 |
| --- | --- |
| `analyze_*` | 靜態分析韌體或資料，不執行原廠程式 |
| `emulate_*`、`probe_*` | 用 Unicorn 執行原廠指令或自製 ARM 程式 |
| `verify_*` | 只讀檔案、重新核對先前輸出 |
| `build_*` | 編譯自製原生程式或 Android App、組圖資 |
| `install_*`、`stage_*` | 寫入車機（會核對身分、備份、讀回、可還原） |
| `check_*` | 研究 checkpoint 的完整性稽核 |
| `publish_*` | 更新研究狀態與報告網頁 |
| `seal_*` | 為一輪實驗輸出產生雜湊封存 |
| `serve_*` | 區網報告與下載服務 |

檔名帶 `_v2`、`_v3` 的是同一工作的新版；舊版保留以對應當時的實驗紀錄。

## 實驗紀錄的讀法

`staging/` 下每輪實驗通常有：

- `proof.json`：結論與檢查項目。
- `seal.json`：輸出檔案的 SHA-256。
- `*terminal*receipt*.json`：實際執行的結束碼與輸出。
- 失敗的嘗試也保留（如 `*-failure.json`），不會被覆寫成成功。

## 執行環境

- Python 3.13；模擬需要 Unicorn 2.1.4（系統套件 2.1.0／2.1.1 曾在部分 GUI 模擬時崩潰，研究時另建 venv）。
- 藍牙：BlueZ、BlueALSA 4.3.1（標準 `org.bluealsa` 服務名稱）、FFmpeg。
- ARM 編譯：`arm-linux-gnueabi-gcc`（freestanding、`-nostdlib`），目標 ARM1176／ARMv6、soft-float。
- Android：API 35 platform jar、D8、AAPT2、apksigner。

## 重要限制

很多腳本預期原始檔在 `/root/garmin`，並需要 repo 裡沒有的原廠韌體（`main_02bd.bin`、GCD）、
完整備份或圖資才能重跑。只有程式碼與結論在這裡；要完整重現須自行從自己的機台取得這些輸入。
