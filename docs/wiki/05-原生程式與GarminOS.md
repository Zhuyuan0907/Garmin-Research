# 05 原生程式與 GarminOS

這頁整理「在原機加入自製程式」的研究。大部分結果來自用 Unicorn 模擬器執行**原廠韌體的指令**，
搭配明確宣告的測試輸入（fixture）。模擬通過不等於車機上可行，每項 proof 都記錄了哪些部分是 fixture。

## 程式載入入口

- 原廠 TTS 語音包的 `DLLIMG.BIN` 由原廠載入器（initializer `0x23C3C4`）讀入固定 3 MiB 保留區，
  做重定位、匯入 99 項主程式 API、註冊 40 個 export。
- 完整外層流程已離線執行：列舉 `*.vpm` → 解析 metadata → 掛載 → 讀 DLL → 初始化。
- 把自製程式附加在原廠語音程式之後，可保留原有 40 個語音介面不變。
- **實機證明**：修改過的美玲語音包讓 Aud Ver 顯示 M7Q9（程式寫入的標記），以及 WFFF（12 個音訊狀態條件快照）。
  兩次都精確還原，使用者冷開機確認回到 2.10。

## OS20 核心

已在模擬器內用原廠指令跑通：

- 工作程序建立（`0x521E5E`）、事件 POST／WAIT、context 切換與恢復、優先權搶占、自行結束。
- mutex 的 owner／遞迴／等待佇列與優先權繼承、condition 等待與廣播。
- 計時器工作與 tick、記憶體配置器（heap、private page）。
- 延遲浮點（lazy VFP）的第一次啟用與跨工作程序交換。

## 音訊

- 原廠音訊來源（kind 10／11 記憶體來源）→ 18 通道佇列 → 每通道混音器工作 → 輸出管理器，整條流程已離線執行。
- 自製元件：媒體佇列、SBC 解碼、FIR 重取樣（44.1／48 kHz → 16 kHz）、持續音源、停止與資源回收。
- 對原廠公開與底層音源入口共 22 處加上保護，防止其他程式在播放中誤用私人槽位。
- 修正過的原廠邊界問題（只在模擬中觀察）：未支援 AVDTP 指令回覆格式、START 長度 8 位元計數繞回、
  Configure 送出失敗後狀態不回滾等。

## 菜單與畫面

- 自製元件可在原廠自訂主選單登錄「Pi 播放器」，由原廠 SQL 選格、建立按鈕、掛入頁面、派送觸控事件。
- 原廠字型載入流程能讀外部 DFHei 字型並查到「播放器」的字形；圖示與文字已畫到模擬畫布。
  預覽圖：`staging/native-player-resources/loaded-player-RGB565-preview.png`（模擬畫布，不是車機截圖）。
- 一般首頁 PageMainMenu 的建構、控制器與前景顯示仍在逐步復原相依項目。

## 尚未解決

- 原機上實際可寫的 MAIN／cache 狀態、真正的開機順序與 UI 執行緒時機。
- 所有寫入者的獨占權、未進入的回呼的存活保證、完整 STOP_DONE、安全卸載與重新載入。
- 語音包簽章（DLLIMG.SIG）在更高層是否驗證。
- 與導航語音的實際共存、硬體 DAC 時脈與喇叭輸出。

所以目前**沒有**可安裝的原生播放器；`staging/` 內標示 `EMULATION-ONLY` 的封裝只供模擬，不可傳到車機。
