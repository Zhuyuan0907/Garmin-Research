這是台灣 nüvi2565RT、HWID1352／8.00 原廠 OS20 橋接路徑的研究筆記，沒有建立實機 App 或新任務。

原廠 `521D7C` 用十五筆、每筆64bytes的索引比對 record+48 的 native task word；這是適配層索引容量，不是整個作業系統只有十五個任務。傳入非零、找不到會正常回傳0；傳入0且沒有空槽，會到 `23D6E8` 的診斷呼叫，包含 `Out of OS20 tasks` 與原建置檔路徑。測試在呼叫前停住，没有模擬該診斷函式会返回或讓車機恢復。

`521DB0` 先讀原current task，執行原 IRQ save／restore，再查索引。找不到時以0再查空槽，實際寫入狀態byte+44=0、native task word+48、priority index+8=0x59。九個離線情境有八個完整返回、一個錯誤呼叫邊界；沒有配置記憶體或建立任務。索引、current TCB及堆疊都是明示測試輸入，不代表實機空槽狀態。

`521E5E` 原建立路徑以參數1／100呼叫 `395440`，再將要求的workspace bytes加152傳到 `39544C`。原建構與TCB流程之後由 `521D7C` 選一個空適配槽，填入回呼／參數等欄位，最後原POST送出工作。`521E44` 為原入口，找到自己的適配record，呼叫 record+12 的函式，r0來自 record+16。這些建立／配置／callback完整流程僅靜態分析，沒有在這份guest執行。

原建立流程没有在已恢复的本体內先檢查配置結果或空槽，再做多處指標寫入；可能依賴原配置器／呼叫端保证，該保證尚未核實。priority表的完整界限與caller第5參數意義仍待確認。不要把靜態signature當可直接呼叫的SDK，也不能在語音初始化中盲目建立工作。

資料在 `staging/native-os20-task-index-v2/`，大型逐指令記錄用gzip，没有複製MAIN。此橋接提供後續研究延後啟動App的候選路徑；原heap、實機CPU／記憶體、GUI就緒時點與任務退出／回收仍未完成。
