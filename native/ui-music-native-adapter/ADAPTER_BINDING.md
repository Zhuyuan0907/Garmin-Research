This component adds compiled native adapters to the frozen UI/music controller. It is specific to Taiwan nüvi 2565RT, HWID 1352, software 8.00. No emulator, original firmware instruction, device/service, sound, native patch installation or integrated App is executed by this verification. The produced ARM ELF is relocatable and is not a loader image or transferable package.

The controller's five frozen sources remain unchanged. The new adapter binds its function table explicitly; it does not link a prior native music build into this ARM artifact. Host tests compile the unchanged controller C as a test dependency, then run the actual adapter C over typed private-state and native byte-array fixtures. The original-address imports and new ARM cleanup bridge are compiled but are never executed on the host.

`original_imports.c` supplies original IRQ save21B6CC, restore21B6DC, current task358D25 and normal-context post2FCF44. Its exact continuous-module map binds the immutable manifest's `music_runtime_cancel`, `source_worker_completed` and data symbols. Every address is checked against that manifest by the build script. This map is valid only for that exact loaded variant; a single-bootstrap relink must regenerate all addresses. The map helper deliberately returns BINDING_MISSING and does not invent exclusive ownership, coherent stream/session preparation, residency or controller function bindings.

`cleanup_bridge.S` is only for the identified single-r0 source-record signature at original3B9DFC. It is not a general heap callback or multargument trampoline. It preserves caller record/result, callee-saved r4-r8 and LR; captures the incoming caller LR; retains a64-byte typed frame; aligns SP to8 for C calls; and restores the original caller SP/LR and original r0 return value. The original10-byte Thumb prologue is f0b5050000202e0087b0. Its dedicated ARM continuation reproduces push{r4-r7,lr}, r5/r0/r6 setup and subsp28, then branches to original Thumb3B9E07. This follows the existing frozen source_event_hooks ABI. The new wrapper has been assembled, not natively executed.

Bind a resident context once with `umcn_set_cleanup_bridge` before exposing the wrapper. The one replacement call site must target this wrapper instead of the old full source completion wrapper; do not chain both or run original cleanup twice. `umcn_cleanup_begin` accepts only the exact bound native record, captures generation/cookie/actual source token/entry LR, and retains the whole callback reference before original cleanup. Only after the full original continuation returns does `umcn_cleanup_after_original` record matching cleanup, forward the unchanged original source_worker_completed for every record, then release the whole frame reference. A preempting source actor during that original notification cannot observe STOP_DONE while the wrapper reference is held. Duplicate after-return handling is rejected. Foreign records preserve the old notification without certifying controller cleanup.

No original MAIN site or old source has been modified. `3B9DFC` hook installation, source-loop service/return hooks, original coordinator publication hook, stream admission hooks, actual native ownership witness, session glue and legal GUI launch are all still integration requirements. Stop completion does not grant safe module unload, native TCB/stack reclamation or exclusion of arbitrary future callbacks. All module/controller/context/callback/stack storage remains resident.
