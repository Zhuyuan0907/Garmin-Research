This is a freestanding control prototype for the exact Taiwan HWID 1352 / software 8.00 integration. It does not contain a task creator, native audio implementation, Bluetooth service, GUI constructor, loader entry, MAIN patch or installable package. Its ARM artifact is a relocatable object/ELF for a future separately linked image. Host adapter tests exercise control logic only.

The caller supplies zero-initialized, resident `umc_controller` storage after the single common bootstrap. The config, adapter table, context, code and callback targets must remain mapped for all future callbacks. `umc_init` rejects a live controller. There is no unload/reset/destructor API. Stop never calls worker shutdown or frees TCBs, stacks, opaque handles or UI objects. The ownership cookie identifies a private native route lease; a nonzero integer does not establish actual exclusive channel ownership.

Use one controller for channel8 phone music. The optional source9 WAV route is a separate configuration and must have a mutually exclusive native ownership adapter; it does not replace the phone objective. `umc_runtime_ready` is called on the existing source actor only after the full native coordinator initializer has returned, its result/owner are verified, and decoder/source task readiness and route ownership have been observed. Merely calling this function does not prove those prerequisites.

`metadata_enter`/`metadata_leave` bind original IRQ save21B6CC/restore21B6DC for short metadata sections. `current_actor` binds original358D25. `wake_source` binds original normal-context post2FCF44 on the already-existing source TCB, using event0x80000 only after this bit is confirmed available in the final task event contract. All native/post/observe/prepare/cancel adapters run with metadata exclusion released. The existing source worker services durable pending state through `umc_service`; a wake failure leaves the command resident and `umc_kick` retries its wake without allocating a new generation. No new task is created.

`prepare_start` runs on that same source actor. For channel8 it validates the existing native runtime and ownership, and prepares local reception or a separately characterized AV-locked live-session resume. It never writes SEP state or synthesizes a remote START, packet or successful audio ACK. Keep original configuration, START, session, packet, source-busy and format guards. A failed or uncertain preparation enters ERROR_PINNED; a later explicit Stop may request reconciliation through the existing cancellation pipeline.

`umc_request_start` accepts a new nonwrapping generation only in IDLE/STOPPED with no active service, media lease or callback lease. It queues the request and returns a token. It does not activate sound. `umc_request_stop` closes local admission immediately, invalidates admission identity, cancels a pending Start and returns the same active generation. Start during STOPPING returns busy. Duplicate Stop returns the existing token without another cancel request. An idle Stop does not manufacture a completion generation. A Stop that arrives while `prepare_start` waits for an original synchronous ACK wins over its late return.

Bind `umc_admission` to the existing stream's configuration/START preaccept paths, event17 resume branch, F1 enqueue branch and consumer checks. Call it in the existing AV mutex protocol; it supplements, rather than replaces, the original gate/policy/runtime checks. A locally stopped controller rejects all five entry points even if the remote SEP still streams. Event17 cannot restart the private queue until a new explicit local Start succeeds. This is local discard/stop, not an AVRCP pause or a remote AVDTP Suspend command.

Selected/copying/decoding media takes a unique noncopyable `umc_lease` with `umc_media_acquire`, rechecks `umc_media_current` before publication, and releases it exactly once on every exit path. Release wakes a STOPPING actor. The lease must remain on the caller's resident stack or in its owned slot; do not copy or forge it. The existing stream's session and queue epoch checks remain necessary. This module cannot roll back PCM that was already committed before Stop; it blocks new admission and completion while covered work remains.

Capture `(route, control generation, ownership cookie, native source token)` from the tracked owned anchor/node before the original callback/cleanup can switch tasks. The native source token is the actual owned anchor ticket or recovered node identity, distinct from the private controller cookie. `umc_source_started` observes original owned publication/start and includes publication that races Stop. It does not call native START. A later remote suspend/resume within one local generation must use a new token only after prior cleanup has returned and the original native ownership/busy guards permit replacement. An old-token cleanup cannot certify the new source.

Wrap the entire reader/cleanup wrapper lifetime with `umc_callback_acquire`/`umc_callback_release`, including the original return, notification post and any immediate context switch. `umc_cleanup_returned` is called only after the full original3B9DFC cleanup body has returned, with the captured token. It records matching cleanup and wakes the source actor; it never changes state to STOPPED. The final callback release wakes the actor again, preventing an in-flight wrapper from leaving completion stranded. The module stays resident even after all currently covered callbacks return; these counters do not prove exclusion of callbacks that have not yet entered.

For channel8, `request_cancel` delegates to the unchanged `music_runtime_cancel` and existing source worker/coordinator. The coordinator retains sole ownership of original36AF75 stop, original277675 node removal, `memory_output_release` and `continuous_media_cancel_ready`. No adapter directly clears active audio, bypasses native states or pretends that request0 means completion. For source9, use the separately characterized owned native stop/public270537 clear pipeline. Actual36AF75/30EDD4 ignores the native37BCE4 send result; dropped requests must remain STOPPING or ERROR_PINNED rather than report success.

`observe_stop` fills every field of `umc_stop_evidence` at a serialized owner boundary without mutating native state. It reports the matching route/generation/cookie/token; actual channel ownership; returned cancellation pipeline; native idle state; zero native methods/provider/mixer/driver/list/calls/readers; zero coordinator, anchor, private queue and owned work. A published channel8 source additionally requires matching recorded cleanup plus returned original node removal, anchor release and FIFO discard. A published source9 requires matching cleanup and returned original queue clear. A never-published generation requires an explicit owner/cancellation barrier and no-source witness; absence of a callback alone is insufficient. All currently covered media and callback leases must be released before STOPPED is published.

The native state witnesses bind to the existing coordinator's checks: source record034E6F08+channel*520 byte2; mixer034E5378+channel*304 byte84; driver034E32BC+channel*84 halfword; source state034E9398+channel equal1; record+F4 methods68 bytes clear; list count+1C0; native_calls/reader_in_flight; coordinator busy/ticket/cancel_pending; memory_output active anchor/provider pool; queue producer/consumer/pending; and owned busy/count. The adapter must establish actual list/pool reservation and prevent stale/new native publication across this boundary. IRQ exclusion and private ownership cookies alone cannot establish that contract.

The host suite supplies deterministic mocks for all these witnesses and interleaves calls inside preparation and observation. It checks original-operation return witnesses separately and runs ASan/UBSan, but executes no original firmware instructions, guest IRQ, actual native mutex, scheduler, device audio or phone packets. It cannot prove real source reservation, callback exclusion, native timing, physical mute, GUI touch/display, navigation coexistence, accepted VPM/SIG or safe module unload.

Minimal next integration: link this component into a new single-bootstrap namespace; create an adapter around the already-existing source worker and exact stream hooks; bind matching source generation/token before original cleanup; wire legal original GUI launch to request APIs; then run one same-VM native Start/Stop/restart case with full original task/memory/ownership guards. Existing frozen GUI and music proofs remain separate until that new integration is actually executed and proved. No current EMULATION-ONLY package is an installation candidate.
